# VOCABI — Decisions log

One line per decision: what was decided, why, and when. Append-only; never edit a past line's meaning — add a new line that supersedes it if a decision changes.

1. **`unmasteredTarget`** = count of all verified, not-yet-mastered senses in the track, independent of placement; but in minutes/day and on-track cost estimates, senses in bands with `p_b ≥ 0.8` are costed at verify-first price (~8s), not full teach price — keeps "target" meaning stable while still crediting placement for cost purposes. (2026-10-02)
2. **MasteryRing** renders a dynamic 1–3 segments matching the sense's required layers (never a fixed 3 with greyed-out slots), fixed order recognition→context→production; the aggregate ring (`/session/done`, `/progress`) always shows 3 segments = share of all senses requiring+passing that layer; every ring ships a text alternative (`aria-label`), never color-only — resolves DESIGN.md's fixed-3 claim vs ENGINE.md's variable layers while keeping the aggregate view meaningful. (2026-10-02)
3. **Recognition distractor shortfall** is fixed at content time: a new distractor-only lexicon (verified glosses, never taught) is added as a content source, and `content:check`'s "fewer than 3 eligible recognition distractors" becomes an ERROR (not warning) for shipping senses. Bounded runtime fallback (should never fire): widen to ±2 bands, then show the item as practice-only (doesn't count toward mastery) and log an error — a mastery-gating question must never be weakened at runtime. (2026-10-02)
4. **On-track formula**: `neededMinutesPerDay = (newLearningCost + projectedReviewCost) / max(daysLeft − taperDays, 1)`, reusing §7's existing time constants; `newLearningCost` uses verify-first cost for `p_b ≥ 0.8` bands; `projectedReviewCost = senses × requiredLayers × reviewsPerLayer (CALIBRATE, default 4) × perLayerReviewTime`; inside the taper window "needs more" fires only if today's due reviews exceed the budget; no exam date → no status shown. Hysteresis (trip above 110% of `minutesPerDay`, clear below 95%) needs memory, so the pure engine function takes `previousStatus` as an explicit input and `ProgressStore` persists the last computed status — keeps the engine pure while avoiding UI flicker near the threshold. (2026-10-02)
5. **Waitlist retention**: purpose-bound — the email is used only to announce Pro. Deleted 30 days after the Pro-launch announcement, or 12 months after signup, whichever comes first; delete-on-request anytime via a contact address on `/privacy`, fulfilled within 30 days; no marketing use, no sharing; consent timestamp + privacy-notice version stored per row; a scheduled-deletion job goes on the Phase 1 backlog — more precise than an open-ended retention promise and matches how the email is actually used. (2026-10-02)
6. **Streak freeze** uses a rolling 7-day window, not ISO weeks (Israeli weeks start Sunday): store `lastFreezeDayKey`; a missed day is covered only if no freeze was used in the previous 6 local days; two consecutive missed days always break the streak — avoids an ISO-week-boundary edge case ever granting two freezes back to back. (2026-10-02)
7. **Pseudoword pronounceability** has no algorithmic test; human review (Roie) flags it in the existing CSV review step. Automated in `content:check`: reject any pseudoword within Damerau-Levenshtein distance ≤2 of a real word/inflection among the top ~20,000 most frequent English words (not the full lexicon — DL≤2 against everything would reject almost every candidate), and require pseudoword length 7–10 characters (short strings collide at DL≤2 by chance far too often). Human check rejects real words in other languages, slang, and brand names. (2026-10-02)

31. **Placement bands are a disjoint, data-computed partition of lemmas**: every lemma belongs to exactly one band; ACAD = academic-list lemmas (NAWL, open license) with frequency rank > 3000, removed from B4/B5, so Σ p_b × size_b never double-counts. Band sizes (including ACAD) are computed at content-build time and stored in `content/placement/bands.json` (Zod `PlacementBands`); `src/engine/config.ts` keeps only the rank boundaries, never sizes. Units are lemmas, not word forms (wordfreq ranks forms — lemmatize or use a lemma-based list). The real file is built in M5; until then tests use `src/engine/fixtures/bands.json`. Supersedes the open "ACAD size" gap in ENGINE.md §4. (2026-10-03)
32. **Placement order and truncation details** (ENGINE §4 left them open): real items run in strictly ascending band blocks B1 → B5 → ACAD (ACAD ranks above 3000); 5 of 10 pseudowords sit at random slots 2-20 (so ≥ 4 in the first 20 and never first), the rest later. Early stop is checked after every answer against the last two completed bands, and truncation skips the remaining pseudowords too (≥ 4 were already answered, which is all reliability needs), going straight to verification; it never fires after the last band (nothing higher to skip). `scorePlacement` refuses an unfinished test, so an unreached band is never mistaken for a skipped one. Answers are persisted in plan order keyed by item id; a mismatch is treated as corrupted state. (2026-10-03)
33. **The scored placement output stays exactly `{ low, high, perBand, reliable, truncated }`**; the point estimate is a separate `estimateKnown(perBand, sizes)` helper so property tests can prove the interval contains it without putting a single number where the UI could show it. The high bound is clamped again after rounding up to 250, because Σ size_b now comes from data (#31). (2026-10-03)
34. **Typo tolerance never accepts a different real word**: with only our small content DB, "quite" typed for "quiet" would pass as a DL-1 typo. Each sense therefore stores `nearWords` — top-20k reference words (+ attested regular inflections) within DL ≤ 1 of an accepted answer of ≥ 5 characters, minus the sense's own forms (lemma, its regular inflections, answers; family members stay in, they are different words) — computed at content-build time by `pnpm content:near-words` and kept current by `content:check` rule 12 (`NEAR_WORDS_STALE`). `checkAnswer` treats an input equal to a nearWord as wrong + confusion pair, never a typo. The reference list stays out of `src/` (#28). Inflections for this list must under-generate (an invented form would turn a genuine typo into "wrong"), so a base is inflected only when the list already holds its -ed/-ing form. (2026-10-03)
35. **Recognition distractors are sampled uniformly from the combined eligible pool** (the track's senses + the distractor-only lexicon), not lexicon-first: the lexicon fills shortages naturally, and seeing taught words as distractors is extra exposure. Picks keep mutually distinct glosses (#30); short at ±1 → ±2 → practice-only, unchanged (#3). (2026-10-03)
36. **Lapse (ENGINE §3)** = an Again on a required layer that already had at least one successful (Hard/Good) review. It demotes the sense to `learning` until that layer's next successful review. A first-ever failure on context/production is not a lapse, so it does not take `recognized` away; the sense was never past that layer. A card's `successes` and `lastRating` are kept beside the ts-fsrs card (ts-fsrs `lapses` counts only Review-state failures). (2026-10-03)
37. **Mastery horizon instant**: a future exam date (day key after today's) means the local start of the exam day (`zonedDayStart`), the conservative end of "retained until the exam". Otherwise (no exam, exam today or past) it is local midnight 30 local calendar days ahead plus the time elapsed since today's local midnight, not now + 30 × 24h, matching §8's no-24h-multiples rule. On a 23/25-hour DST day this can land one wall-clock hour off, which is harmless for a 30-day retrievability check. (2026-10-03)
38. **Raw review log** = `{ senseId, layer, rating, reviewedAt (ISO UTC), outcome: "correct" | "wrong" | "dontKnow", ms, typo, mode: "learn" | "practice" | "verify" }`, one per review, returned together with the new card state so no review can skip its log. `replayCard` rebuilds a card from logs (sorted by time) using the **stored** rating, so a later `SLOW_MS` change never rewrites history. The raw outcome fields let Phase 0 data recalibrate the CALIBRATE thresholds. Replay equality is tested. ts-fsrs fuzz stays at its default (off), so scheduling is deterministic. (2026-10-03)
39. **Streak with a clock moving backwards**: when today's day key is earlier than the stored last-session key (flying west across midnight, or a manual clock change), `recordSession` changes nothing and `displayStreak` keeps the streak; neither ever decrements or breaks it. The freeze window is checked against the missed day: covered iff `daysBetween(lastFreezeDayKey, missed) ≥ 7`. (2026-10-03)
40. **In-session relearning**: a wrong or "I don't know" answer re-queues the item once, as an unrated practice copy at least 3 items later (3 other items in between; at the end if fewer remain), only while the plan's estimated seconds stay within the budget; a copy is never re-queued again. The FSRS rating of a layer is recorded once per local day (the first answer), so relearning never double-rates. (2026-10-03)
41. **"I know this"** in the learn step never rates a card: it removes the sense's pending practice items and schedules a recognition check at least 3 items later in the same session (within the 30-minute cap; otherwise it acts as "continue"). The check behaves like verify-first: correct → recognition rated, other layers follow; wrong → Again + normal teach flow. (2026-10-03)
42. **The session plan is deterministic and persistable**: `buildSession` takes a `seed` instead of a live `rng` and returns plain JSON (`v: 1`); every item's question rng is `mulberry32(seed ^ fnv1a(itemId))`, so items inserted later still get stable MCQs. The caller stores the state after every event (the store itself is M6); replayed or out-of-order events are rejected; a plan from an earlier local day is stale and rebuilt. (2026-10-03)
43. **Spacing within a session**: a new sense is never tested right after its learn step; immediate testing measures seconds-long memory and inflates the first FSRS rating. Learn steps are grouped; each sense's first practice item and each next layer (recognition → context → production) come at least `relearnGap` (3) other items later. When too few items exist, a greedy scheduler keeps the order and makes the gap as large as the items allow; trailing due reviews are moved into the new block as spacers. (2026-10-03)
44. **Session fill details**: a card is due when it is due by the end of the local day and was not rated today; a started sense missing a required layer's card (interrupted session, or passed verification) gets practice items for those layers before new senses. `introducedToday` (from `sensesIntroducedOn(logs)`) makes the new-word quota daily: the exam quota subtracts its count, the 40% share subtracts its cost. A new sense enters the plan only if its whole unit fits, in strict track order. (2026-10-03)
45. **Extra practice after "done for today"** offers two choices: (1) "learn N more new words" — normal new-sense units (verify-first applies), rated normally, counted as introduced today, within the 30-minute cap; (2) "review weak words" — the weakest started, unmastered cards, never rated. Supersedes the single unrated extra-practice idea from the P4b plan. (2026-10-03)
46. **Session/on-track interpretations confirmed for P4b**: a correct verify-first/"I know this" check is rated by §2 (Good, or Hard when slow or with a typo), not always Good; inside the taper window the status uses the same 110%/95% hysteresis on today's due-review minutes; "no new words unless nothing else is due" falls back to the 40% share when nothing is due (exam today included); a past exam returns `examPast` (prompt to update, no status) and new words follow the no-exam rule; verify-first follows placement even when `reliable` is false, and nothing is verify-first without placement; with no `previousStatus` the plain 100% threshold decides. (2026-10-03)
47. **Relearning overflow** (amends #40): relearning copies may push the session past its budget by up to max(50% of the budget, 2 minutes), never past the 30-minute cap — a 5-minute session ends by 7.5 minutes, a 20-minute one by 30. Only relearning copies use the overflow; follow-ups after a passed check stay within the budget and teach flows after a failed check within the cap, as before. (2026-10-03)
48. **Daily new-sense ceiling** (amends #45): the 30-minute cap stays per session, and new senses per local day (regular + "learn N more") never exceed `dailyNewMax = max(2 × plannedNewPerDay, 20)` (CALIBRATE). `plannedNewPerDay` is the regular quota's daily plan: ceil(unmasteredTarget / (daysLeft − 14)) with an exam beyond the taper window, otherwise the senses that fit the 40% share of the daily budget. When the ceiling is reached, "learn more" is not offered (`done.extra.newWords = false`, `newWordsLeft = 0`). `projectTomorrowReviews(input, n)` returns the extra reviews (count and seconds) due by the end of tomorrow if the learner takes n more now, simulated with ts-fsrs assuming correct answers on every required layer, so the UI can show "more words today = more reviews tomorrow". (2026-10-03)
49. **No consecutive items of one sense** (generalizes #43): for every item kind — reviews (e.g. two due layers of one word), missing-layer practice next to the same word's review after an interrupted session, relearning copies, checks and inserted teach flows (the teach card after a failed check comes next-but-one) — two neighbours never share a sense when another order exists. A repair pass after building and after every event moves the nearest other item in between, never past an item of its own sense (each sense's order is kept) and never splitting the learn group; it prefers moves that keep every gap ≥ min(3, its old gap). Only items from the cursor on are moved. (2026-10-03)
50. **#49 repair, last resort** (amends #49): when no single move into a same-sense pair removes it (BABAA, where each sense must keep its order), the remaining plan is rebuilt in the order closest to the current one that has no neighbours: each step takes the earliest item that is next in its sense's order, isn't of the previous item's sense, and leaves a remainder that can still be ordered (every sense fits in alternate slots). It succeeds whenever such an order exists and never splits the learn group. Weak-words sessions are repaired too. (2026-10-03)
51. **Lemma ranking for the bands** (`content/reference/lemmas-en.tsv`, `scripts/content/lemmas.ts`): the top 80,000 wordfreq 3.1.1 forms are aggregated to lemmas. A form goes to its NGSL 1.2 / NAWL 1.2 family first (authoritative: they fold irregular forms and British spellings); otherwise a dictionary word (WordNet 3.1 ∪ NGSL ∪ NAWL ∪ CEFR-J) is its own lemma; otherwise WordNet's morphy lemmatizer (wink-lemmatizer: verb, noun, adjective) gives the first dictionary candidate. A British base spelling folds to its American variant only if that variant is a dictionary word and more frequent (with an exception list: four, hour, advertise…). Contraction pieces (t, s, ll, don…) are never counted, and "won" is not folded into "will". Lemmas that WordNet writes only capitalized (London, Paris) are dropped unless on a source list; lemmas with any capitalized WordNet entry carry a `proper` flag. Each lemma also lists the other ranked lemmas it is a form of (`formOf`: found → find). Ranks follow summed frequency, ties alphabetical. (2026-10-03)
52. **`content:check` rules 13-14** `BANDS_STALE` (bands.json missing or not what `pnpm content:bands` computes) and `PLACEMENT_BAND` (an item's band differs from its lemma's band, or the lemma is in no band). They recompute the partition from the committed reference files, the same pattern as rule 12. The loader exposes `bands` (null until the file exists). (2026-10-03)
53. **Placement bank** (`pnpm content:placement`): 30 lemmas per band, a seeded shuffle of the eligible lemmas in rank order. Ineligible: a lemma that is also an inflected form of a different lemma (`formOf`; a learner may say "yes" because they know found as find), a proper noun not on NGSL/NAWL/CEFR-J, fewer than 3 letters or not a-z, no vowel (abbreviations), and the curated offensive-word, Hebrew-loanword and names/abbreviations lists (`content/reference/exclude-*.txt`; the loanword list also covers international words Israelis know from Hebrew, e.g. concept, therapy, inflation; to be confirmed by Roie in `review/placement-items.csv`). These words stay in the ranking and the band sizes. Pseudowords (`pnpm content:pseudowords`): 50 deterministic syllable-table strings that pass rule 9 through the same code as the validator (`scripts/content/pseudo-rule.ts`), and stricter than the rule: not any form in lemmas-en.tsv, not a known word plus an ending ("treeful"), no vowel hiatus, no medial 3-consonant clusters. 50 so that at least 40 survive human review. (2026-10-03)

55. **AMIRNET starter selection** (`pnpm content:starter` → `content/input/amirnet-starter.csv`, 150 rows): candidates = NAWL ∪ Noa ∪ CEFR-J B2 lemmas, minus NGSL 1.2 SFI top 1000. Tier 1 = all of NAWL ∩ Noa; then NAWL-only and Noa-only alternate (NAWL covers reading texts, Noa's list sentence completion), each by wordfreq lemma frequency, ties by CEFR-J B2 membership then lemma; CEFR-J-B2-only only if both run out. A phrase is as frequent as its rarest word and takes that word's band (unranked word → frequency 0, B5).
