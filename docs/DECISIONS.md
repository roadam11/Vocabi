# VOCABI — Decisions log

One line per decision: what was decided, why, and when. Append-only; never edit a past line's meaning — add a new line that supersedes it if a decision changes.

1. **`unmasteredTarget`** = count of all verified, not-yet-mastered senses in the track, independent of placement; but in minutes/day and on-track cost estimates, senses in bands with `p_b ≥ 0.8` are costed at verify-first price (~8s), not full teach price — keeps "target" meaning stable while still crediting placement for cost purposes. (2026-10-02)
2. **MasteryRing** renders a dynamic 1–3 segments matching the sense's required layers (never a fixed 3 with greyed-out slots), fixed order recognition→context→production; the aggregate ring (`/session/done`, `/progress`) always shows 3 segments = share of all senses requiring+passing that layer; every ring ships a text alternative (`aria-label`), never color-only — resolves DESIGN.md's fixed-3 claim vs ENGINE.md's variable layers while keeping the aggregate view meaningful. (2026-10-02)
3. **Recognition distractor shortfall** is fixed at content time: a new distractor-only lexicon (verified glosses, never taught) is added as a content source, and `content:check`'s "fewer than 3 eligible recognition distractors" becomes an ERROR (not warning) for shipping senses. Bounded runtime fallback (should never fire): widen to ±2 bands, then show the item as practice-only (doesn't count toward mastery) and log an error — a mastery-gating question must never be weakened at runtime. (2026-10-02)
4. **On-track formula**: `neededMinutesPerDay = (newLearningCost + projectedReviewCost) / max(daysLeft − taperDays, 1)`, reusing §7's existing time constants; `newLearningCost` uses verify-first cost for `p_b ≥ 0.8` bands; `projectedReviewCost = senses × requiredLayers × reviewsPerLayer (CALIBRATE, default 4) × perLayerReviewTime`; inside the taper window "needs more" fires only if today's due reviews exceed the budget; no exam date → no status shown. Hysteresis (trip above 110% of `minutesPerDay`, clear below 95%) needs memory, so the pure engine function takes `previousStatus` as an explicit input and `ProgressStore` persists the last computed status — keeps the engine pure while avoiding UI flicker near the threshold. (2026-10-02)
5. **Waitlist retention**: purpose-bound — the email is used only to announce Pro. Deleted 30 days after the Pro-launch announcement, or 12 months after signup, whichever comes first; delete-on-request anytime via a contact address on `/privacy`, fulfilled within 30 days; no marketing use, no sharing; consent timestamp + privacy-notice version stored per row; a scheduled-deletion job goes on the Phase 1 backlog — more precise than an open-ended retention promise and matches how the email is actually used. (2026-10-02)
6. **Streak freeze** uses a rolling 7-day window, not ISO weeks (Israeli weeks start Sunday): store `lastFreezeDayKey`; a missed day is covered only if no freeze was used in the previous 6 local days; two consecutive missed days always break the streak — avoids an ISO-week-boundary edge case ever granting two freezes back to back. (2026-10-02)
7. **Pseudoword pronounceability** has no algorithmic test; human review (Roie) flags it in the existing CSV review step. Automated in `content:check`: reject any pseudoword within Damerau-Levenshtein distance ≤2 of a real word/inflection among the top ~20,000 most frequent English words (not the full lexicon — DL≤2 against everything would reject almost every candidate), and require pseudoword length 7–10 characters (short strings collide at DL≤2 by chance far too often). Human check rejects real words in other languages, slang, and brand names. (2026-10-02)
8. **Anonymous auth (Phase 1)** design is deferred, but the fact that anonymous Supabase users get the full `authenticated` Postgres role (RLS must branch on the `is_anonymous` JWT claim, not role) is pinned now. As a Phase 0 consequence, the local `ProgressStore` must be migratable to the server without data loss: versioned schema keyed only by stable sense ids, raw review logs stored (not just derived FSRS state), `exportAll()`/`importAll()` with a round-trip test — this is Phase 0 scope (PRODUCT.md, ENGINE.md, ROADMAP M6), not deferred with the rest of Phase 1. (2026-10-02)
9. **Placement item count**: PRODUCT.md's "~40 yes/no items" is corrected to "~44 items (30 real across 6 bands + 10 pseudowords + up to 4 verification MCQs)" to match ENGINE.md exactly — removes an ambiguity about whether verification MCQs were already included. (2026-10-02)

23. **`<En>` renders `<bdi dir="ltr" lang="en">`**, not `<span class="isolate">`: Tailwind's `isolate` utility is `isolation: isolate` (stacking context), not `unicode-bidi: isolate`, so the old spec would not have isolated bidi at all; `<bdi>` is `unicode-bidi: isolate` by default in every browser. DESIGN.md and CLAUDE.md wording updated. (2026-10-02)
24. **Control boundaries use a new `--line-strong` token** (light #8C8578, dark #756E61; 3.18-3.74:1 on bg/surface/surface-2): `--line` (1.2-1.5:1) fails WCAG 1.4.11's 3:1 for component boundaries, and `--ink-2` was visually too heavy for the calm direction. `--line` stays for decorative dividers/card outlines only; selected chips on `--accent-soft` use an `--accent` border (`--line-strong` is under 3:1 there). Accent-tinted surfaces carry `--ink` text because `--accent` on `--accent-soft` is 4.33:1 in light. The focus ring is a 2px `--accent` outline with a 2px offset, so it stays visible around accent-filled controls. All pairs are checked by `src/design/contrast.test.ts`. (2026-10-02)
25. **Theme override without flash**: the preference is stored in `localStorage` key `vocabi-theme` (`light`/`dark`; absent = follow `prefers-color-scheme`). A tiny inline `<head>` script in the root layout (a server component) sets `data-theme` on `<html>` before `<body>` is parsed, so there is no flash and no hydration dependency. The e2e test proves it with all app JS blocked. Storage failures fall back to system. next/font CSS variables are named `--nf-*` to stay clear of Tailwind's `--font-*` theme namespace. (2026-10-02)

26. **English serif is Fraunces** (over Newsreader, after the `/design` side-by-side). next/font loads its `opsz` axis (9-144) so 40-48px headwords use the display optical size via `font-optical-sizing: auto`, plus the `WONK` axis: with that axis loaded the browser default rendered the wonky alternates (leaning h/n/m — pixel-identical to `WONK 1`), which read as quirky at headword size, so `.font-en-serif`/`.font-fraunces` pin `font-variation-settings: "WONK" 0`. The ProgressBar track gets the same centered `--line-strong` hairline as the MasteryRing track (#24, WCAG 1.4.11), covered by the accent fill. Screenshot baselines regenerated intentionally for both changes. (2026-10-02)
27. **ACAD band adjacency**: for "frequency band ±1" (recognition distractors, `content:check` rule 11), ACAD — academic words not in B1-B3 — is adjacent to B4, B5 and itself; B1-B5 are linear. Implemented once in `src/engine/distractors.ts` (`bandsAdjacent`) and shared by the validator and the M4 engine. (2026-10-02)
28. **Rule 9 reference list** = wordfreq 3.1.1 `top_n_list("en", 20000)` (data CC-BY-SA 4.0), committed as `content/reference/top20k-en.txt` and regenerated reproducibly by `pnpm content:build-reference`, which downloads the pinned PyPI wheel, checks its sha256 and decodes the bundled data in Node (no Python needed). It is internal validation data only: `src/` may not import or read it, enforced by an ESLint `no-restricted-syntax` ban and a Vitest grep guard (`scripts/content/reference-guard.test.ts`). Source, version and license are in `content/SOURCES.md`. (2026-10-02)
29. **M3 content-format details not spelled out in CONTENT.md**: Track = `{ id, order }` (the session builder's "track order"), PlacementItem = `{ id, lemma, band }`, Pseudoword = `{ id, text }`; track/sense membership mismatches are rule-1 errors (`TRACK_REF`). Schemas are strict and a `verified` record must carry `reviewedBy`/`reviewedAt`. Rule 11 runs only on *verified* shipping senses (unverified ones already fail rule 8), and devOnly senses/lexicon entries count only for devOnly targets, mirroring what each build loads. All interpretations are listed in CONTENT.md "Validator rules". (2026-10-02)
30. **Rule 11 counts distractors with mutually distinct glosses**: the 3 wrong options of a recognition MCQ are Hebrew glosses, so two candidates sharing a normalized gloss (e.g. two lexicon entries both "להשיג") count once; picked greedily (may undercount, never overcounts — safe for a mastery gate, `docs/DECISIONS.md` #3). Also from the M3 spec review: `CLOZE_EQUALS_EXAMPLE` compares word sequences (punctuation-only differences still match), and a track file must be named `tracks/<id>.json`. (2026-10-02)
34. **Typo tolerance never accepts a different real word**: with only our small content DB, "quite" typed for "quiet" would pass as a DL-1 typo. Each sense therefore stores `nearWords` — top-20k reference words (+ attested regular inflections) within DL ≤ 1 of an accepted answer of ≥ 5 characters, minus the sense's own forms — computed at content-build time by `pnpm content:near-words` and kept current by `content:check` rule 12 (`NEAR_WORDS_STALE`). `checkAnswer` treats an input equal to a nearWord as wrong + confusion pair, never a typo. The reference list stays out of `src/` (#28). Inflections for this list must under-generate (an invented form would turn a genuine typo into "wrong"), so a base is inflected only when the list already holds its -ed/-ing form. (2026-10-03)
