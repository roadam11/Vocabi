# ערכת הפתיחה של VOCABI

הערכה הזו הופכת את תוכנית המוצר לחומר עבודה עבור Claude Code. כל הקבצים מיועדים לשורש הריפו. הם כתובים באנגלית, כי ככה Claude Code עובד הכי מדויק, והטרמינל לא מציג עברית טוב. הטקסטים של הממשק עצמו יהיו בעברית, בקובץ אחד מרוכז.

## מה יש כאן

| קובץ | תפקיד |
| --- | --- |
| `CLAUDE.md` | ״חוקת הפרויקט״. Claude Code קורא אותו בתחילת כל שיחה. הוא קצר בכוונה |
| `docs/PRODUCT.md` | מה בונים בשלב 0, מסכים, אירועי מדידה, ומה לא בונים |
| `docs/ENGINE.md` | האלגוריתמים: מבחן השיבוץ, בדיקת תשובות, מסיחים, בניית תרגול, שליטה, רצף ימים, ורשימת מקרי קצה שחייבים בדיקה |
| `docs/CONTENT.md` | מבנה רשומת מילה, חוקי הבדיקה האוטומטית, סטנדרט התרגום ושרשרת התוכן |
| `docs/DESIGN.md` | מערכת העיצוב: צבעים (עם בדיקת ניגודיות), גופנים, חוקי ימין לשמאל, רכיבים, נגישות |
| `docs/ROADMAP.md` | אבני הדרך M0 עד M9, ולכל אחת קריטריונים של ״גמור״ |
| `PROMPTS.md` | הפרומפטים לפי הסדר, P0 עד P9, מוכנים להדבקה |
| `.claude/agents/` | שני סוכני ביקורת: אחד בודק התאמה למפרט, השני בודק ימין לשמאל ונגישות |

## איך עובדים (פרוטוקול לכל פרומפט)

1. **שיחה נקייה:** מתחילים כל פרומפט בפקודה `/clear`.
2. **מצב תכנון:** לוחצים Shift+Tab עד שבשורת המצב מופיע `⏸ plan mode on`, או מפעילים עם `claude --permission-mode plan`. במצב הזה Claude קורא ומתכנן, אבל לא משנה קבצים.
3. **קריאת התוכנית:** בודקים שהיא תואמת את אבן הדרך. אפשר לערוך אותה ישירות עם Ctrl+G. רק אז מאשרים.
4. **ביצוע:** Claude מממש בקומיטים קטנים ומריץ את כל הבדיקות.
5. **ראיות, לא הצהרות:** לא מקבלים ״סיימתי״ בלי פלט של הפקודות וצילומי מסך. זה כתוב כחובה בקובץ CLAUDE.md.
6. **ביקורת:** Claude מפעיל את סוכן הביקורת על השינוי ומתקן רק את מה שפוגע בנכונות או בדרישות.
7. **כשנתקעים:** אחרי שני תיקונים שלא עבדו, `/clear` ומתחילים מחדש עם פרומפט מדויק יותר. ממשיכים מסשן קודם עם `claude --continue`.

## הסדר

**לפני הכול (M0, אתה):**
- ריפו פרטי באתר GitHub.
- Node בגרסת LTS, ‏pnpm, ‏Claude Code.
- חשבונות Vercel, ‏Supabase וגם PostHog.
- מפתח API של Anthropic. הוא משמש רק את סקריפטי התוכן, אף פעם לא את האפליקציה.
- מעתיקים את הערכה לשורש הריפו. **לא** מריצים `/init`, כי הוא ידרוס את CLAUDE.md שכבר כתבנו.

**P0, ביקורת מפרט, בלי קוד:** Claude עובר על כל המסמכים, מחפש סתירות ובודק שהגרסאות של הכלים עדכניות. אחר כך הוא שואל אותך עד 8 שאלות וכותב את התשובות לקובץ `docs/DECISIONS.md`. זה חוסך ימים של עבודה על הנחות לא נכונות.

**P1 עד P9:** פרומפט אחד לכל אבן דרך. אבן דרך גדולה יכולה לקחת יותר מסשן אחד.

**במקביל, החלק שלך בתוכן (M5):** אתה בודק כל אחת מ־150 המילים הראשונות בקובץ CSV שנפתח באקסל. אלה בערך שעתיים עד שלוש שעות של עבודה, והן הדבר הכי חשוב בניסוי: אם תרגום אחד שגוי, המשתמש מאבד אמון.

## שלוש החלטות שלך לפני P0

1. **אירוח:** המסלול החינמי של Vercel מיועד לשימוש לא מסחרי. ניסוי בלי תשלומים הוא אזור אפור. אפשר להתחיל בחינם ולעבור למסלול בתשלום (בערך 20 דולר לחודש) ביום שמופיע כפתור תשלום, או לעבור מיד.
2. **רשימות המקור לתוכן:** לשלב 0 מותר להשתמש ברשימות פתוחות לדגימה פנימית. לפני השקה ציבורית צריך לבדוק רישוי (פירוט בקובץ CONTENT.md).
3. **גופן המילה באנגלית:** Newsreader או Fraunces. מחליטים אחרי M2, כשרואים את שניהם על הטלפון.

## מה לא לעשות

- לא לדלג על P0.
- לא לבקש ״תבנה את כל האפליקציה״ בפרומפט אחד.
- לא לאשר תוכנית בלי לקרוא אותה.
- לא לרכך את בודק התוכן כדי שיעבור.
- לא לבנות שום דבר מעבר לשלב 0 לפני שנבדק השער הראשון: לפחות 30% מהמשתמשים חוזרים ביום השני.
